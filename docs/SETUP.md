# 実行環境と制約

## 準備

1. 利用権限のあるWebPerformer-NX環境を用意します。
2. PC版は `exports/desktop/AppDef_46815190/`、モバイル版は `exports/mobile/AppDef_60476142/` をアプリ定義のインポート元として確認します。
3. インポート先の実行環境を選択し、DB接続名・ファイルパス・アプリの画面遷移を確認します。実行環境IDは公開用に空にしてあるため、元の環境へ自動接続しません。
4. SQLが参照する `EC` のDB設定とテーブル定義を用意します。元ZIPにはDBのDDL・接続設定・実データがなく、このリポジトリだけで完全なDB再構築はできません。TODO処理では `id`、`todo_name`、`todo_date`、`check_box` を参照しています。型や制約は元の設計と照合してください。
5. TODOの登録・表示・編集・削除、期日なしの入力、完了状態の変更、PCとモバイルの画面遷移を検証します。必要な組み込み画面はプラットフォーム側で生成・設定してください。

手順の基準は公式の[アプリケーションのインポート説明](https://docs.webperformer.jp/ja/manuals/application/)です。インポート先によってDB名やファイルパスの変更が必要です。

## 既知の確認事項

- モバイルTODOの削除成功後の遷移先に `MBILE_CARENDER` というコードが残っています。定義にある画面コードは `MOBILE_CARENDER` です。原本のロジックは維持しており、実行前に修正・確認が必要です。
- 認証なしの設定と無効なCSP設定が元のアプリ定義に含まれます。本番向けの認証、認可、CSP、入力検証、SQLパラメーターの扱いを確認せずに一般公開しないでください。
- DBのDDL・実データや、元環境の動作画面を示すスクリーンショットは提供されていません。
- 定義ファイルから確認できる実装と、実際に動作確認された内容は区別しています。この登録作業では元の実行環境での検証は行っていません。
